# Integral University — BCA & MCA Project Showcase (2027)

**Department of Computer Application · Integral University, Lucknow**  
**Academic session:** 2026–2027 · **Repository year:** 2027

## Overview

This repository contains a responsive, static project showcase suitable for GitHub and Vercel:

- `index.html` — responsive UI, programme/group filters, search, group selection, copy-repository-name action.
- `data/projects.json` — year-specific configuration and all 225 team/project slots. Update this file to maintain project details.
- `README.md` — naming rules, full team directory, and deployment/update instructions.

## Programme capacity

| Programme | Groups | Teams per group (maximum) | Total slots | Project ID prefix |
|---|---:|---:|---:|---|
| BCA | A–L (12 groups) | 15 | 180 | `PUGID` |
| MCA | A–C (3 groups) | 15 | 45 | `PPGID` |

Each team can have up to five members. A team slot is listed even when its official project title, description, technology stack, or repository URL has not yet been supplied. Such fields are marked as pending in the showcase; do not treat generated project IDs as confirmed university allocations until they have been checked against the official project register.

## Repository naming convention

Use the repository year, project ID, and two-digit team ID in each repository name:

- **BCA:** `BCA2027-<PROJECT-ID>-<TEAM-ID>` — example: `BCA2027-PUGID26001-H09`
- **MCA:** `MCA2027-<PROJECT-ID>-<TEAM-ID>` — example: `MCA2027-PPGID26001-C09`

Display team IDs with two digits (`A01`, `H09`, `C09`, `L15`); use the same team ID in the repository name.

Repository URL examples: [BCA2027-PUGID26001-H09](https://github.com/Integral-Software-Solutions/BCA2027-PUGID26001-H09) and [MCA2027-PPGID26001-C09](https://github.com/Integral-Software-Solutions/MCA2027-PPGID26001-C09). These are naming examples; confirm that the repositories exist before treating the URLs as live.

### Generated slot range in this starter

- BCA: `BCA2027-PUGID26001-A01` through `BCA2027-PUGID26180-L15`.
- MCA: `MCA2027-PPGID26001-A01` through `MCA2027-PPGID26045-C15`.

**Important ID note:** the requested example endpoints `PUGID26001` to `PUGID2027` and `PPGID26001` to `PPGID2027` do not form an ascending numeric sequence. This starter uses sequential IDs beginning at `PUGID26001` / `PPGID26001` for 180 / 45 slots. Confirm the official ID allocation before creating repositories; if the registrar has a different ID scheme, update the `projectId` and `repositoryName` fields in `data/projects.json`.

## Updating project details

Edit `data/projects.json`. Each project object supports these fields:

```json
{
  "programme": "BCA",
  "group": "A",
  "teamNumber": 1,
  "teamId": "A01",
  "projectId": "PUGID26001",
  "title": "Approved project title",
  "description": "Short project description",
  "technologies": ["Java", "Spring Boot", "MySQL"],
  "repositoryName": "BCA2027-PUGID26001-A01",
  "repositoryUrl": "https://github.com/Integral-Software-Solutions/BCA2027-PUGID26001-A01",
  "demoUrl": "",
  "liveUrl": "",
  "status": "complete"
}
```

- Keep `programme` as `BCA` or `MCA`.
- `group` must match a configured group; `teamNumber` is 1–15.
- Use `status: "pending"` until the record is ready, and `status: "complete"` when project details are complete.
- `repositoryUrl`, `demoUrl`, and `liveUrl` must be real URLs. The UI does not invent or link to repositories that have not been supplied. A generated repository name is a naming template, not proof that a repository exists.
- Keep each `projectId` unique unless the official project register explicitly says otherwise.
- The UI safely escapes text fields and uses only supplied URLs for outbound links.

## Changing the year next session

Most annual changes should be made in `data/projects.json` only:

1. Update `config.meta.session` and `config.meta.repositoryYear`.
2. Update group lists, project ID prefixes, and starting IDs under `config.programmes` if required.
3. Update every record's `projectId` and `repositoryName` according to the approved repository policy.
4. Add/remove records to match actual groups and team counts.
5. Update the visible session text in `index.html` if you want the page header to show the new year. For a completely configuration-driven year label, replace that static text with a small render target in a future revision.

The rendering, filtering, search, responsive layout and group selection are kept separate from the project data so the UI normally does not need to be rewritten each year.

## Local preview

Because the page loads JSON with `fetch`, run it from a local static server rather than opening `index.html` directly as a `file://` URL. For example, with Python installed:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000` from the project folder.

## Deploy to Vercel

1. Push the contents of this folder to a GitHub repository.
2. In Vercel, select **Add New → Project** and import that repository.
